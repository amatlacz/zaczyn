# Orchestration by host

`zaczyn-orchestrate` applies when named or when the user explicitly requests cost-aware orchestration. The current session's capable model owns task routing, integration, and the final result. Inspect actual tools, model choices, permissions, and limits in the running host before delegating. The skill requires no separate user approval for each agent, though host permission checks still apply. A skill reference cannot enable a tool or change a host permission. If no real delegation is available, work in the current agent and say so. A manual handoff is an option only when the user asks for one.

| Host | Supported route to inspect | Model and effort control |
|---|---|---|
| Claude Code | [Subagents](https://code.claude.com/docs/en/sub-agents) can be selected automatically or invoked for focused work; custom agents can define tools and permissions. | A subagent definition or invocation can select a model and effort, subject to current version, environment settings, and availability. Check the effective model; inheritance and forced settings can override expectations. |
| Codex | [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents) can be spawned and coordinated when enabled in the session. | Explicit spawn settings, agent defaults, or custom agent files can set model and reasoning effort where supported. Otherwise agents inherit parent settings. ChatGPT Work can require an explicit delegation request at its current intelligence level. |
| Kiro | [Subagents](https://kiro.dev/docs/custom-agents/subagents/) and opt-in [workflows](https://kiro.dev/docs/workflows/) provide focused or background delegation across supported clients. | [Custom agents](https://kiro.dev/docs/custom-agents/) can specify a model; [Web autonomous mode](https://kiro.dev/docs/web/autonomous-mode/) selects its model automatically. Inspect client, configuration, and permission prompts. |
| Antigravity | No delegation or per-worker model route is assumed by this adapter. | Inspect the running host before claiming either capability. |
| Microsoft Copilot (Cowork, Chat) / Copilot Studio | Copilot Cowork plans and runs multistep tasks with its own orchestration; this adapter assumes no user-controlled delegation or worker model there. [Declarative agents](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/agents-overview) use Copilot's orchestrator and models. [Copilot Studio](https://learn.microsoft.com/en-us/microsoft-copilot-studio/guidance/generative-orchestration) can orchestrate configured tools, topics, and child agents. | Declarative instructions do not select a worker model. Custom engine agents can bring their own models and orchestration, but require a separate implementation. Only configured resources can be invoked. |
| GitHub Copilot | [IDE custom agents](https://docs.github.com/en/copilot/how-tos/copilot-in-your-ide/use-copilot-agents/use-custom-agents) are a distinct product path; supported profiles can specify a model. | Inspect IDE and agent configuration. Do not infer these controls from Microsoft 365 Copilot or Copilot Studio. |
| Browser chat projects | Use the uploaded reference and project instructions when supported; [ChatGPT Projects](https://help.openai.com/en/articles/10169521-projects-in-chatgpt) provide project files and instructions. | A project reference does not grant subagent, filesystem, or model-selection controls. Inspect actual session tools and confirm the reference remains available in a fresh chat. |

Delegation may improve elapsed time or context isolation, but it adds model calls and can cost more. In particular, same-model subagents are not presumed cheaper. Use bounded, independent tasks and compare available prices or usage data when cost matters. Keep host permission checks in force; orchestration does not bypass them. Fresh-install execution in supported hosts remains unverified.

## Microsoft and browser reference path

For Microsoft Copilot (Cowork and Copilot Chat) use the single-file edition and the [Microsoft 365 guide](https://github.com/amatlacz/zaczyn/blob/main/adapters/microsoft-365/README.md); for other browser chats use the [single-file edition](https://github.com/amatlacz/zaczyn/blob/main/adapters/single-file/README.md) or the chat edition. Orchestrate is not shipped as a single file, because these apps expose no delegation the skill can control. Do not add personal AGENTS or PROJECT documents to a shared agent's knowledge (Agent Builder or Copilot Studio): everyone with access to that agent could read them. A plain browser chat may need the files attached again in each conversation; do not claim persistence until checked.
