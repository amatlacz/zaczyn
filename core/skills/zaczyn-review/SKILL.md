# Review

Give the user an evidence-based assessment that helps them decide what to do. Read [workspace conventions](../../references/workspace.md).

1. **Identify the artifact and mode.** Is this review-only, review-and-fix, or completion of authorized work? Use the current request, not assumptions about the command name. Inspect the exact version/files; ask if the target is ambiguous. Existing closed work may be reviewed without reopening it unless new work is requested.
2. **Find the criteria.** Use the agreed task intent or the legacy brief. For an external artifact with no brief, derive criteria from the user's review request and relevant supplied standards; clarify only consequential ambiguity. Label these as the criteria for this review, not a past agreement. No historical brief or work item must be manufactured.
3. **Check the evidence.** For each material criterion, report met, partial, missed, contradicts, or not verified, with the observed evidence and how it supports the grade. Missing access, files, or checks means not verified. A file path alone does not prove its contents satisfy the criterion. Also assess usefulness for the actual audience; report material gaps the rubric missed. If criteria are wrong, propose and document a revision rather than quietly grading against a weaker bar.
4. **Resolve findings within scope.** Each gap is fixed and rechecked, explicitly accepted with rationale under the user's authority, or unresolved. A lesson is optional and never resolves a gap. Review-only requests report findings without editing the artifact. Review-and-fix requests authorize suitable corrections within their scope; do not re-ask permission for each routine fix. Changes to purpose or acceptance of material gaps remain user decisions. Mention extras only when they affect usefulness, scope, or cost.
5. **Record the appropriate outcome.** For a managed task, put findings and evidence in its Review section or its existing review.md. A large independent review can be separate with a pointer. For a standalone review, a response is enough unless a saved artifact was requested or retained evidence is needed. No forced task folder or decision log.

## Completion and pause are different

Only completion mode closes an open task, and only after each material gap has been fixed/rechecked or explicitly accepted. Keep accepted partials and unverified items distinct from met in the outcome. Record counts when there is a criterion list; never inflate them. Unresolved work remains open with the next action.

An explicit cancellation or early closure can close with a clear reason and retained gaps; skipped steps remain skipped. A mid-task review or “stop for today” leaves the task open. No lesson is required. For consequential work, suggest an independent reviewer/session when useful without claiming that a fresh chat guarantees correctness.

If a reusable improvement emerges, offer [grow](../zaczyn-grow/SKILL.md); do not silently add rules while reviewing an artifact.
