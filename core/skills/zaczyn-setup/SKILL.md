# Setup

Help the user build an understandable setup that fits their purposes, including possibilities they would not know to request. Read [workspace conventions](../../references/workspace.md). Inspect available context before interviewing; a task mentioned during setup may illustrate the user's needs rather than authorize execution.

1. **Establish scope and depth.** Reuse stated choices; otherwise offer quick (aim for roughly two minutes), guided, or deep. Establish whether this is one project, recurring work in a role, or a personal assistant. Explain the difference in ordinary language. If the user is unsure, recommend guided and ask before treating it as selected. An explicit quick/deep request needs no additional depth menu.
2. **Discover and suggest.** Use [discovery guidance](references/discovery.md) at the chosen depth. Learn enough about goals, recurring work, material, existing tools, and working preferences to offer concrete possibilities. Respond to answers with useful examples and recommendations, not just more questions. Ask only the next useful group of questions; let the user skip, stop, or return later. Do not force a profession category, technical vocabulary, or a long questionnaire.
3. **Make the setup reviewable.** Summarize what is understood and propose the smallest useful set of context, rules, templates, procedures, and capabilities. Explain what each addition helps with and any meaningful trade-off. Separate selected items from optional ideas and unanswered decisions. An example deliverable may demonstrate a proposal; do not produce the real task's deliverables while the user is still choosing their setup.
4. **Implement selected additions.** Existing explicit authorization carries forward. For capability additions use [customization guidance](../../references/customization.md): inspect what is available, configure or install within the selected scope when supported, and verify actual access. Otherwise give the precise user action or a usable alternative. Do not call recommendations installed. For skills, use an available skill creator or save an explicitly invoked recipe; do not assume native discovery.
5. **Save portable context.** For a new local workspace, adapt [AGENTS](../../assets/AGENTS.md) for how to work and [PROJECT](../../assets/PROJECT.md) for facts and scope. Add only the host wrapper the adapter requires. Reuse and merge existing instructions without overwriting them; keep old context authoritative until an explicit migration. In a chat project, prepare the equivalent named documents and saving instructions through the chat edition. Save useful known context even for quick setup; omit empty sections and task scaffolding.
6. **Close or checkpoint setup.** Summarize what is ready, proposed, unverified, or waiting for input; show where personalizations live and how to revise them. Offer a clear choice: start the first task, customize further, or stop. End after setup unless the user explicitly selected work or requested setup followed by execution. When that is already authorized, continue with [work](../zaczyn-work/SKILL.md) without asking again.

For partial or deep setup, save a short Setup section in PROJECT with the selected scope/depth, decisions, completed additions, unresolved questions, and next action. On resumption read it and the actual files; continue the chosen thread rather than restarting the interview. A completed quick setup needs only a concise result, not a separate setup report.
