# Work

Help the user reach the intended result with only the process that helps this task. Read [workspace conventions](../../references/workspace.md).

## Pick the next action

| Situation | Action |
|---|---|
| Clear, small, reversible task with adequate context | Do it directly. No task note or extra setup interview. |
| Resume, a pause, or interrupted work | Use [checkpointing](references/checkpointing.md); identify the intended item and inspect its actual state. |
| Plan-only request or work with meaningful dependencies | Use [planning](references/planning.md). A plan-only request ends with the plan. |
| Existing authoritative domain workflow | Follow it; link its context and checkpoints where needed. Do not create a second plan. |
| Missing essential agreement or material | Clarify the next consequential decision; do independent work while it remains open. |

Normal follow-ups continue within the selected task without rerunning this triage. A new clearly named task should not be interrupted by a menu of unrelated open items. Follow the workspace conventions for an explicit archive request; no separate skill is needed.

## Establish enough intent

Use existing project/task context; do not require a setup ritual or a particular brief filename before helping. Agree the useful outcome and a few concrete checks, using the user's examples, standards, and material. If the framing may be wrong, ask a natural question such as “What would make this unhelpful?” Do not ask it mechanically.

Only create a task note when work needs durable agreement, cross-session progress, or retained evidence. Use the template resolution in the workspace conventions. Include unresolved assumptions or constraints that affect the next step; label criteria as proposed when they have not been agreed. Routine criteria directly derived from an explicit request need no separate approval ceremony; ambiguous consequential choices do.

For unfamiliar work, borrow only useful [working patterns](references/patterns.md). The user should not need to select a profession, route, or pack. An unavailable tool is a limitation to resolve, not a reason to fabricate output or claim a check passed.

## Carry out the work

Read the relevant selected-procedure pointers in AGENTS or the existing authority. Use those domain skills and available tools; a recipe marked unverified must not be treated as an installed capability. Work in useful increments; verify each significant step and update the existing progress record when one exists. Pause only at an actual unresolved decision, dependency, permission boundary, or requested gate. If new evidence changes the agreement, show the change and retain its dated reason before dependent work continues.

When the user pauses, checkpoint without closing. When the intended result is ready, apply [review](../zaczyn-review/SKILL.md) in completion mode; it owns the checking and closure rules. A quick job's checks can stay in the response. Do not make the user invoke a second command for routine completion checking.

Finish with the result/path and any material limitation, or the saved next action if unfinished. Mention [grow](../zaczyn-grow/SKILL.md) only when the user wants an adaptation or real repetition/friction makes one useful; no mandatory lesson.
