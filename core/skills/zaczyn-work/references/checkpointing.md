# Resume and pause

Find the intended task from the request and workspace pointers. Scan task/brief metadata only as far as needed to locate it; read the selected record rather than all historical work. Ask if several candidates genuinely fit. A naming collision does not authorize overwriting an existing item.

For new-format work, read task.md. For old-format work, read brief.md plus plan.md/review.md if present. For a domain workflow, follow its recorded authoritative paths. Resolve conflicting authority pointers before proceeding.

Inspect the referenced outputs and any material check results. Treat “complete” in a ledger as a claim to reconcile with the files, not proof. State what is ready, what remains, and the next action. Do not repeat answered interview questions or generate another brief.

On an intentional pause, or before handing unfinished work back, update the existing Progress location with:

- What exists and the relevant output/source paths.
- The last check actually observed and its result; distinguish anything not checked.
- The blocker, missing answer, or approval gate, if any.
- The next concrete action.

Keep status open. For a legacy task without a plan, use a brief Progress section; do not create a plan solely to hold a checkpoint. No task note is needed for a completed quick job. An unexpected termination may prevent a final checkpoint, so record progress at meaningful increments during longer work rather than only at the end.

When updating current progress, reconcile stale step labels with the observed state while retaining dated history; do not leave the active summary contradicting the checkpoint.
