# Optional working patterns

Use only the pattern that helps the current task; combine patterns when needed. These are examples of method, not a classification of the user's profession or a required folder scaffold.

| Need | Useful approach |
|---|---|
| Compare or research | Identify the decision and comparison dimensions; distinguish sourced facts from assumptions; preserve sources supporting material claims. |
| Explain or present | Agree the audience and central message; try an outline or sample before investing in layout when that reduces rework. |
| Calculate or analyze | Identify inputs, units, missing data, and the check for the calculation; inspect the output with suitable tools rather than trusting formatting. |
| Build or modify software | Inspect the current engineering workflow and checks; use its authoritative plan and conventions. No default framework installation. |
| Repeat a task | Complete or inspect a representative example; identify what changes between runs before proposing a reusable recipe. |
| Explore something unfamiliar | Choose a small question that can be answered with available material; ask for a standard, reference example, or knowledgeable reviewer when needed. |
| Coordinate outputs or instances | Name each artifact's authoritative location and owner/update convention. Introduce tracks/shared material only when that resolves actual copying or coordination problems. |

An unusual task can use none of these. Agree its useful outcome, material, next action, and check directly.
