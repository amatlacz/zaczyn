# Planning when it helps

Begin from available intent, not a requirement for a particular file. Shape an incomplete outcome before committing to dependent steps, without redirecting the user through a separate skill just to obtain a brief.

Use a short Steps section in the task note by default. For each meaningful step, state what it produces, how to check it, and any real dependency or decision. Refer to criterion IDs where useful; ensure every criterion has a check without duplicating the entire rubric in a second table.

Preserve an existing external plan as authoritative. Create a separate plan only when the detail obscures the task summary, independent review needs it, or the user requests it; link rather than copy. No duplicate end-state and risks sections merely to fill a template.

If a gate is needed, name the decision and who makes it. Existing approval carries forward unless the agreed scope changes. External audience alone does not mean every step needs approval. A plan-only request does not authorize execution.

Track observed progress as pending, underway, checked, or skipped in ordinary prose or a small table. A skipped step retains its reason; it never becomes checked just because the task closes. A change of scope gets a dated reason in the authoritative task record.
