# When the process gets in the way

| Symptom | Try this |
|---|---|
| Setup starts producing your example deliverable before you chose a setup. | Treat the example as discovery context; finish the setup choice before starting work. |
| A deep interview never reaches a usable result. | Pause, save the decisions and next setup question, and start with the selected additions. |
| The assistant says a suggested tool is installed or a download is remembered. | Ask what operation verified access or saved the project source; otherwise record it as proposed or prepared. |
| A small edit triggers another interview and new files. | Give the edit directly; keep the current context and skip a task note. |
| You repeat the same preference in every chat. | Add one scoped rule to AGENTS.md or the existing authoritative instructions. |
| A skill tries to handle every kind of work. | Narrow its trigger or let the relevant domain workflow own the task. |
| A successful task produces another obligatory lesson. | Keep a lesson only when it changes future work usefully. |
| You maintain two plans with different progress. | Select one authoritative plan and link to it. |
| A rule made sense once but now causes friction. | Ask grow to revise or retire it, retaining a way to undo the change. |
| A review says “passed” but offers no actual check. | Ask for observed evidence and a clear list of what remains unverified. |
| A polished template hides missing information. | Label the unknowns and resolve those that affect the next action. |

More folders, tools, or instructions are not a measure of progress. Judge the process by the useful result and how much explanation and maintenance it saves.
